## Future Roadmap

### فاز ۲: «هتل متصل» (ماه ۴ تا ۹)

- ✅ **میزبانی داخل ایران با PocketBase** انجام شده است ([`pocketbase/`](../pocketbase)). گام بعدی فقط وقتی مقیاس آن را لازم کند:
- **بک‌اند اختصاصی داخل ایران:**
  - NestJS یا Go با **PostgreSQL** (و TimescaleDB برای سری زمانی).
  - Redis، و Keycloak یا Auth داخلی.
  - Docker و استقرار روی دیتاسنتر داخلی.
  - همان قرارداد API v1 ([۰۶](06-api.md)).
  - اپ فقط یک `RestBackend` adapter اضافه می‌کند ([۰۴](04-flutter-architecture.md)).
- **مسیر مهاجرت بدون توقف:**
  1. `RestBackend` در اپ.
  2. همگام‌سازی دوطرفه یا export از Firestore به PostgreSQL.
  3. سوییچ هتل‌به‌هتل با `ZH_BACKEND`.
  4. خاموش‌کردن Firebase.
- **Push داخلی:** پیاده‌سازی `PushService` با سرویس ایرانی (مثلاً Pushe یا Najva)، یا WebSocket یا MQTT مستقیم.
- **اتصال PMS** (سیستم رزرو و پذیرش): پرکردن خودکار `dailyOperations` و وضعیت اشغال اتاق‌ها.
- **IoT مرحلهٔ ۱:** کنتورهای هوشمند برق، آب و گاز از طریق n8n یا گیت‌وی MQTT و `POST /energy/readings`، با دادهٔ ساعتی.
- **AI:** پیش‌بینی انرژی و اشغال، و تشخیص ناهنجاری آماری.
- **محصول:**
  - پنل وب مدیریتی (Flutter Web) برای Super Admin و چند هتل.
  - چندزبانه (عربی برای بازار منطقه).
  - اپ مهمان (درخواست سرویس و گزارش خرابی).
- **امنیت:**
  - اجبار `roleOverrides` در لایهٔ سرور.
  - ورود دومرحله‌ای (OTP پیامکی) برای نقش‌های مدیریتی.
  - SIEM برای audit log.

### فاز ۳: «هتل هوشمند» (ماه ۱۰ تا ۱۸)

- **IoT مرحلهٔ ۲:** سنسورهای حضور، دما، رطوبت و نشت آب؛ اتصال به BMS و HVAC (BACnet و Modbus از طریق گیت‌وی).
- **اتوماسیون حلقه‌بسته:** خاموش‌کردن HVAC اتاق خالی، و ایجاد خودکار تیکت هنگام نشت آب. هر دو با سیاست‌های قابل‌تنظیم و audit.
- **Predictive maintenance** برای چیلر، بویلر و آسانسور.
- **بهینه‌سازی شیفت و تخصیص نظافت.**
- **Agent عملیاتی** با تأیید مدیر.
- **زیرساخت:** Kubernetes، معماری microservices برای سرویس‌های پرترافیک (ingestion، analytics و AI)، و صف پیام (Kafka یا NATS).

### فاز ۴: «پلتفرم» (ماه ۱۸ به بعد)

- **Digital Twin** هتل: نقشهٔ طبقات، تجهیزات و جریان انرژی، با شبیه‌سازی سناریوهای «اگر…آنگاه».
- Benchmark زنجیره‌ای و بازار (ناشناس‌شده).
- Marketplace اتصال‌ها: PMS، POS رستوران، حسابداری، تأمین‌کنندگان.
- API عمومی و SDK برای شرکا. SLA سازمانی و استقرار on-premise برای زنجیره‌های بزرگ.

## کارهای فنی باقی‌مانده پیش از تولید

1. **PocketBase و n8n روی لیارا:** مراحل [راهنمای لیارا](09-liara-runbook.md)، و فعال کردن پشتیبان روزانهٔ PocketBase. **Firebase (در صورت استفاده):** اجرای `flutterfire configure --project=zarin-hoshmand`.
2. امضای release: Android keystore (فعلاً debug signing) و iOS provisioning/APNs key در Firebase.
3. Secretها: `firebase functions:secrets:set ANTHROPIC_API_KEY INTEGRATION_SECRET`، و `N8N_WEBHOOK_URL` در `.env.<project>`.
4. Firebase App Check (Play Integrity و App Attest) برای جلوگیری از کلاینت‌های جعلی.
5. CI: `flutter analyze`، `flutter test`، `npm run typecheck`، `npm test` و `npm run test:rules`.
6. تست انتها‌به‌انتهای Functions emulator در CI. در محیط توسعهٔ فعلی (پشت proxy)، تست‌ها handlerها را مستقیم روی emulatorهای Auth و Firestore اجرا می‌کنند.
