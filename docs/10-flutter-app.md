# ۱۰. اتصال اپ Flutter به سرور لیارا (macOS)

این راهنما اپ اندروید را روی Mac اجرا یا build می‌کند و آن را به سرور PocketBase روی لیارا وصل می‌کند:
`https://zarin-hoshmand-nieplltrhr.liara.run`

## پیش‌نیازها

| ابزار | نسخه | توضیح |
|---|---|---|
| Flutter | **3.47 یا جدیدتر** (Dart 3.13.5 به بالا) | `pubspec.yaml` نسخهٔ `sdk: ^3.13.5` را می‌خواهد. با Flutter 3.47.6 بررسی شده است. نصب: `brew install --cask flutter` |
| Android Studio | آخرین نسخه | Android SDK، شبیه‌ساز و JDK را با هم نصب می‌کند |
| Android SDK | Platform 36، Build-Tools 36، Command-line Tools | در Android Studio ← Settings ← Android SDK |
| Android NDK | `28.2.13676358` | همان نسخه‌ای که Flutter 3.47 می‌خواهد. اگر نصب نباشد، Gradle هنگام اولین build آن را دانلود می‌کند |
| JDK | 17 یا 21 | AGP 9.1 و Gradle 9.3.1 دست‌کم JDK 17 لازم دارند. JDK همراه Android Studio کافی است |
| شبیه‌ساز یا گوشی | Android 10 (API 29) یا جدیدتر | `minSdk = 29` |

بررسی:
```zsh
flutter --version                    # Flutter 3.47.x یا جدیدتر
flutter doctor                       # بخش Android toolchain باید بدون خطا باشد
flutter doctor --android-licenses    # یک بار، برای پذیرفتن مجوزهای SDK
```

> **دانلود از سرورهای گوگل از ایران:** `dl.google.com` و `maven.google.com` (Android SDK، NDK و وابستگی‌های Gradle) ممکن است به‌دلیل تحریم با خطای 403 روبه‌رو شوند. در این صورت از DNS ضدتحریم یا یک mirror مخزن Maven استفاده کنید. این مشکل فقط در اولین نصب و build پیش می‌آید.

## اجرا روی شبیه‌ساز

```zsh
cd ~/zarin/app
flutter pub get
flutter emulators                          # فهرست شبیه‌سازها
flutter emulators --launch <نام شبیه‌ساز>    # یا از Android Studio ← Device Manager
flutter run \
  --dart-define=ZH_BACKEND=pocketbase \
  --dart-define=ZH_PB_URL=https://zarin-hoshmand-nieplltrhr.liara.run
```

اگر هیچ شبیه‌سازی ندارید، از Android Studio ← Device Manager یک دستگاه با Android 10 یا جدیدتر بسازید.

## ساخت APK

```zsh
cd ~/zarin/app
flutter build apk --release \
  --dart-define=ZH_BACKEND=pocketbase \
  --dart-define=ZH_PB_URL=https://zarin-hoshmand-nieplltrhr.liara.run
```

- خروجی: `build/app/outputs/flutter-apk/app-release.apk`
- نصب روی گوشی متصل (USB debugging روشن) یا شبیه‌ساز در حال اجرا: `flutter install`، یا `adb install -r build/app/outputs/flutter-apk/app-release.apk`
- برای فایل‌های کوچک‌تر به ازای هر معماری پردازنده، `--split-per-abi` را اضافه کنید.
- **امضا:** این build با کلید debug امضا می‌شود که برای آزمایش و نصب مستقیم کافی است. برای انتشار در فروشگاه‌ها، کلید release بسازید (نقشهٔ راه، بخش «کارهای فنی باقی‌مانده»).
- `ZH_PB_URL` هنگام build داخل اپ قرار می‌گیرد. اگر آدرس سرور عوض شد، APK را دوباره بسازید.

## چک‌لیست آزمون دستی

برای این آزمون حساب مدیرکلی لازم است که `npm run create-hotel` ساخته است: کد ملی او و رمز موقتش.

| # | کار | نتیجهٔ مورد انتظار |
|---|---|---|
| ۱ | صفحهٔ «ورود به سامانه»: «کد ملی» مدیرکل و «رمز عبور» (رمز موقت) را وارد کنید و «ورود» را بزنید | ورود موفق، و رفتن مستقیم به صفحهٔ «تغییر رمز عبور» |
| ۲ | در «تغییر رمز عبور»: «رمز فعلی» (رمز موقت)، «رمز جدید» و «تکرار رمز جدید» را وارد کنید. رمز جدید باید حداقل ۸ کاراکتر شامل حرف انگلیسی و عدد باشد | پیام «رمز عبور تغییر کرد» و نمایش داشبورد مدیرکل، با نوار پایین «داشبورد · اتاق‌ها · تعمیرات · انرژی» |
| ۳ | از «بیشتر» ← «حساب کاربری» ← «خروج از حساب» خارج شوید و دوباره وارد شوید: یک بار با رمز موقت، یک بار با رمز جدید | رمز موقت رد می‌شود و رمز جدید پذیرفته می‌شود |
| ۴ | «بیشتر» ← «کاربران» ← «کاربر جدید»: «کد ملی» (یک کد ملی واقعی و معتبر)، «نام و نام خانوادگی»، «نقش» (مثلاً «تکنسین تعمیرات») و «رمز موقت» را وارد کنید و «ایجاد کاربر» را بزنید | پیام «کاربر ایجاد شد…» و نمایش کاربر در فهرست. فهرست نقش‌ها فقط نقش‌هایی را نشان می‌دهد که مدیرکل مجاز به تعریفشان است |
| ۵ | خارج شوید و با کاربر جدید وارد شوید | این کاربر هم باید رمز موقت را عوض کند و فقط صفحه‌های نقش خودش را می‌بیند |
| ۶ | با مدیرکل: «تعمیرات» ← «ثبت خرابی»: «عنوان خرابی»، «دسته»، «اولویت» و «محل» را وارد کنید و «ثبت و ارسال» را بزنید | پیام «خرابی ثبت شد و به تیم تعمیرات اطلاع داده شد.» و نمایش تیکت در فهرست تعمیرات |
| ۷ | یک خرابی دیگر با اولویت «بحرانی» ثبت کنید | هشدار در «اعلان‌ها» دیده می‌شود. اگر `ZH_N8N_WEBHOOK_URL` تنظیم شده باشد، رویداد به n8n هم می‌رود |
| ۸ | در پنل `/_/` سرور: مجموعه‌های `maintenanceTickets` و `auditLogs` را باز کنید | تیکت‌ها با `reportedBy` مدیرکل ثبت شده‌اند و هر تغییر در Audit log آمده است |

**اگر ورود خطا داد:**
- «کد ملی معتبر نیست»: رقم کنترل کد ملی نادرست است.
- خطای اتصال: آدرس `ZH_PB_URL` در build را بررسی کنید و `https://zarin-hoshmand-nieplltrhr.liara.run/v1/health` را در مرورگر گوشی باز کنید.
- رمز اشتباه: رمز موقت را superuser می‌تواند در پنل `/_/` ← `users` عوض کند. در این صورت فیلد `mustChangePassword` را هم روشن بگذارید.
