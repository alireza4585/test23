# ۱۹. استقرار یکپارچه روی لیارا: از `1544bc1` تا `ai/phase-1`

این سند جای بخش ۶ سند [۱۷](17-ai-phase-0.5.md) و بخش ۸ سند [۱۸](18-ai-phase-1.md) را می‌گیرد. هر سه فاز (دستهٔ ۱، فاز ۰ و ۰.۵، فاز ۱) با **یک** کپی و **یک** restart مستقر می‌شوند. بعد از هر قدم یک فهرست بررسی آمده است. تا همهٔ موارد آن قدم درست نشده‌اند، سراغ قدم بعد نروید.

کل مسیر، از جمله دو راه بازگشت، یک بار به‌صورت محلی تمرین شده است. نتیجه در بخش ۷ آمده است. من هیچ‌چیزی را روی لیارا اجرا نکرده‌ام. `liara deploy` را روی برنامهٔ PocketBase اجرا نکنید.

**سازگاری APK:**

- APK قدیم روی سرور تازه خواندن‌ها را درست انجام می‌دهد، اما **ذخیرهٔ «ثبت روزانه» با `403` رد می‌شود**. این عمدی است ([۱۷، بخش ۵](17-ai-phase-0.5.md#۵-سازگاری-نسخههای-اپ)) و در تمرین هم دیده شد.
- پس APK تازه باید **بلافاصله** پس از قدم ۴ نصب شود. بهترین زمان، ساعت کم‌کار پذیرش است.

**دربارهٔ shell:** دستورهای `zsh` روی Mac شما اجرا می‌شوند. دستورهای `sh` در «خط فرمان» برنامه در پنل لیارا اجرا می‌شوند. هیچ رمز یا کلیدی را در چت نفرستید.

## ۴. کپی migrationها و hookها (استقرار اصلی)

در پنل لیارا ← برنامهٔ PocketBase ← «خط فرمان»:

```sh
B=ai/phase-1
cd /tmp && rm -rf test23-* s.tgz \
  && wget -qO s.tgz "https://codeload.github.com/alireza4585/test23/tar.gz/refs/heads/$B" \
  && tar xzf s.tgz \
  && cp -r test23-*/pocketbase/pb_migrations/. /pb_migrations/ \
  && cp -r test23-*/pocketbase/pb_hooks/. /pb_hooks/ \
  && rm -rf test23-* s.tgz && echo "copied"
```

- migrationها **قبل از** hookها کپی می‌شوند.
- PocketBase تغییر `/pb_hooks` را می‌بیند، restart می‌شود و هر شش migration را یک‌جا به ترتیب اجرا می‌کند.
- **زمان در تمرین:** حدود ۲ ثانیه از کپی تا پاسخ کد تازه، روی ۴۲٬۵۴۸ رکورد. جدول کامل در بخش ۷ است.
- اگر پس از یک دقیقه restart نشد، از پنل لیارا «راه‌اندازی مجدد» بزنید.
- پس از merge (بخش ۸)، `B` همان شاخهٔ اصلی می‌شود.

**بررسی (همه لازم):**

- [ ] `/v1/health` برمی‌گرداند `{"ok":true,…}`.
- [ ] در لاگ برنامه در لیارا خطای migration یا `panic` نیست.
- [ ] Collections: هر ۱۳ collection تازهٔ بخش ۰ وجود دارند.
- [ ] `permissions`: ۳۴ ردیف، از جمله `finance.record` و `ai.actions.approve`.
- [ ] `users`: فیلد `financeView` هست. برای مدیرکل `true` و برای مدیر انرژی `false` است.
- [ ] `dailyFinance`: به ازای هر روزی که درآمد داشته یک ردیف دارد. در تمرین ۴۰۹ ردیف بود، برابر با روزهای دارای درآمد.
- [ ] Settings ← Crons: `zarin_forecasts`، `zarin_energy`، `zarin_insights` و `zarin_briefing` در فهرست‌اند.
- [ ] Settings ← Rate limits: همچنان روشن است. migrationها آن را تغییر نمی‌دهند.

اگر یکی از این‌ها درست نیست، بخش ۶ (بازگشت) را اجرا کنید.

## ۶. بازگشت (فقط اگر قدم ۴ یا ۵ شکست خورد)

### راه A: برگشت کامل به `1544bc1` با بکاپ

هر دادهٔ ثبت‌شده پس از بکاپ قدم ۲ از بین می‌رود. **ترتیب مهم است:** اگر اول بکاپ را restore کنید، PocketBase با migrationهای تازه بالا می‌آید و آن‌ها را دوباره اجرا می‌کند.

1. در «خط فرمان» برنامهٔ PocketBase، شش migration تازه را پاک کنید:

   ```sh
   cd /pb_migrations && rm -f 1760300000_ai_forecasts_recommendations.js 1760300100_notification_dedupe.js \
     1760400000_ai_phase0.js 1760500000_finance_record_permission.js 1760500100_daily_finance.js 1760600000_ai_phase1.js && ls
   ```

   خروجی `ls` باید فقط `1759700000_zarin_schema.js` و `1759800000_outbox_lease.js` باشد.

2. hookهای `1544bc1` را کپی کنید. این کار restart را راه می‌اندازد:

   ```sh
   B=1544bc147a3c455a8b6e58ac56fee756ff9a18a5
   cd /tmp && rm -rf test23-* s.tgz \
     && wget -qO s.tgz "https://codeload.github.com/alireza4585/test23/tar.gz/$B" \
     && tar xzf s.tgz && cp -r test23-*/pocketbase/pb_hooks/. /pb_hooks/ \
     && rm -rf test23-* s.tgz && echo "copied"
   ```

   فایل‌های تازه‌ای که در `/pb_hooks/lib` می‌مانند بی‌اثرند. فقط `zarin.pb.js` بارگذاری می‌شود و آن هم همان نسخهٔ `1544bc1` است.

3. پنل `/_/` ← Settings ← Backups ← بکاپ قدم ۲ ← Restore. PocketBase restart می‌شود.
4. APK قبلی را دوباره نصب کنید.

**بررسی:**

- [ ] `/v1/health` درست است.
- [ ] Collections هیچ‌کدام از collectionهای تازه را ندارد و `permissions` ۳۲ ردیف دارد.
- [ ] «ثبت روزانه» با APK قبلی ذخیره می‌شود.

### راه B: migration down، بدون از دست رفتن داده

درآمدی که پس از استقرار ثبت شده به `dailyOperations` برمی‌گردد و `dailyMetrics` دقیقاً به حالت قبل برمی‌گردد. پیش از آن یک بکاپ تازه بگیرید.

1. در «خط فرمان» برنامهٔ PocketBase:

   ```sh
   echo y | /usr/local/bin/pocketbase migrate down 6 --dir=/pb_data --hooksDir=/pb_hooks --migrationsDir=/pb_migrations
   ```

   خروجی باید شش خط `Reverted …` داشته باشد، از `1760600000` تا `1760300000`.

2. همان دستور `rm` راه A (قدم ۱) را اجرا کنید.
3. همان دستور کپی hook راه A (قدم ۲) را اجرا کنید.
4. APK قبلی را نصب کنید.

**بررسی:** همان سه مورد راه A. در این راه، رکوردهای ثبت‌شده پس از استقرار (تیکت، قرائت و غیره) باقی می‌مانند.

**محیط:**
