# ۱۱. ورود دادهٔ آزمایشی (پارسیان آزادی، ۴۷۵ اتاق)

`npm run import-dataset` بستهٔ دادهٔ آزمایشی را در یک هتل **تازه** با وضعیت `trial` وارد می‌کند. سپس rollup، بینش‌ها و بررسی SLA را برای همان هتل اجرا می‌کند و نتیجه را با شیت `Test_Scenarios` مقایسه می‌کند. بستهٔ داده از دو فایل تشکیل شده است:

- **zip:** فایل‌های CSV و `hotel.json`.
- **Excel:** شیت‌های `App_Users`، `App_Data_Mapping` و `Test_Scenarios`.

**این دو فایل را داخل مخزن نگذارید.** کدهای ملی آزمایشی در آن‌ها هست. مثلاً در `~/Downloads` نگهشان دارید.

## محافظ‌ها

| خطر | محافظ |
|---|---|
| دست خوردن هتل واقعی | مسیر import سرور فقط هتلی را می‌پذیرد که وضعیتش `trial` است و فقط با superuser کار می‌کند. اسکریپت قبل و بعد از import رکوردهای هتل‌های دیگر را می‌شمارد و در پایان `Other hotels: unchanged ✓` چاپ می‌کند |
| از دست رفتن داده | **قبل از هر نوشتنی** از کل `pb_data` بکاپ گرفته می‌شود: یک نسخه روی سرور (پنل `/_/` ← Settings ← Backups) و یک نسخه روی Mac در `import-backups/`. اگر بکاپ شکست بخورد، چیزی نوشته نمی‌شود |
| import دوباره | اگر هتلی با همین نام وجود داشته باشد، یا یکی از کدهای ملی آزمایشی روی سرور کاربر داشته باشد، اسکریپت پیش از نوشتن متوقف می‌شود |
| حساب سراسری | کاربر superAdmin دیتاست (`USR-0002`) ساخته نمی‌شود، چون این نقش به همهٔ هتل‌ها، از جمله هتل واقعی، دسترسی دارد |
| رمزها | رمز موقت کاربران آزمایشی بدون نمایش روی صفحه و دو بار پرسیده می‌شود و جایی ذخیره نمی‌شود. همهٔ کاربران `mustChangePassword=true` دارند |

فایل بکاپ در `import-backups/` کل دیتابیس است، شامل هتل واقعی و hash رمزها. آن را جایی به اشتراک نگذارید. این پوشه در `.gitignore` قرار دارد.

## پیش‌نیاز

1. **Mac:** مرحلهٔ ۱ [راهنمای لیارا](09-liara-runbook.md#۱-آمادهسازی-mac-یک-بار) را انجام دهید، به‌ویژه این دو دستور:
   ```zsh
   cd ~/test23 && git pull
   cd ~/test23/pocketbase && npm ci --omit=dev
   ```
2. **hookهای سرور:** دستور [مرحلهٔ ۲](09-liara-runbook.md#۲-بهروزرسانی-hookها-و-migrationهای-pocketbase) را در خط فرمان برنامهٔ PocketBase در لیارا اجرا کنید. این نسخه دو مسیر import و تحلیل را اضافه می‌کند و یک خطای موتور بینش را هم رفع می‌کند: در هتل بزرگ، کارهای هفتهٔ اخیر از محاسبهٔ کارایی نظافت جا می‌افتادند. اگر این مرحله انجام نشده باشد، اسکریپت پیش از هر تغییری با پیام `the server's hooks are older than this script` متوقف می‌شود.
3. **n8n، پیش از وصل کردن PocketBase به آن:** workflow «01» را طبق [مرحلهٔ ۴](09-liara-runbook.md#۴-بهروزرسانی-workflowها-در-n8n) به‌روز کنید. نسخهٔ جدید فقط رویدادهای هتل‌های `ZARIN_HOTEL_IDS` را می‌فرستد. بدون آن، هشدارهای هتل آزمایشی به گروه‌های بله و پیامک مدیر کشیکِ هتل واقعی هم می‌رسند. تا وقتی `ZH_N8N_WEBHOOK_URL` در PocketBase خالی است (مرحلهٔ ۷ هنوز انجام نشده)، هیچ رویدادی به n8n فرستاده نمی‌شود.

## ۱. دیدن برنامهٔ import (بدون اتصال به سرور)

cd ~/test23/pocketbase

این دستور فقط فایل‌ها را می‌خواند و جدول زیر را چاپ می‌کند. هیچ چیزی روی سرور نوشته نمی‌شود.

«۷ روز اخیر» یعنی 2026-09-30 تا 2026-10-06. مبنای آن «now» شیت `Test_Scenarios` است: 2026-10-07 09:30 به وقت تهران.

## ۲. اجرا

```zsh
ZH_PB_URL=https://zarin-hoshmand-nieplltrhr.liara.run npm run import-dataset -- --csv ~/Downloads/app_import_csv_S1_Normal.zip --xlsx ~/Downloads/ParsianAzadi_Zarin_TestDataset_S1_Normal.xlsx --apply
```

1. ایمیل و رمز superuser پرسیده می‌شود.
2. اسکریپت بررسی‌ها را انجام می‌دهد: به‌روز بودن hookها، تکراری نبودن نام هتل و کدهای ملی. سپس هتل‌های دیگر را نشان می‌دهد، که باید دست‌نخورده بمانند.
3. رمز موقت کاربران آزمایشی دو بار پرسیده می‌شود: حداقل ۸ کاراکتر، با حرف انگلیسی و عدد.
4. برای شروع باید `yes` تایپ کنید.
5. بکاپ گرفته می‌شود و import مرحله‌به‌مرحله پیش می‌رود. روی سرور محلی حدود ۲٫۵ دقیقه طول کشید. از روی اینترنت چند دقیقه بیشتر طول می‌کشد. در این مدت ترمینال را نبندید. اگر سرور `429 Too Many Requests` برگرداند، اسکریپت خودش صبر می‌کند و دوباره تلاش می‌کند.
6. در پایان این‌ها چاپ می‌شود:
   - شناسهٔ هتل آزمایشی؛
   - سطر `Other hotels: unchanged ✓`؛
   - جدول مقایسه با `Test_Scenarios`، که در `import-backups/import-report-<شناسه>.md` هم ذخیره می‌شود؛
   - دستور حذف هتل آزمایشی.

## چه چیزی چطور وارد می‌شود

- **زمان‌ها:** همهٔ زمان‌های CSV به وقت تهران‌اند و به UTC ذخیره می‌شوند (منهای ۳:۳۰). ایران از ۱۴۰۱ ساعت تابستانی ندارد.
- **تاریخچه (قبل از ۷ روز اخیر):** از مسیر import مخصوص superuser وارد می‌شود. hookها برای این رکوردها هشدار، اعلان، رویداد یا تغییر وضعیت اتاق نمی‌سازند. `created` و `updated` هر رکورد همان زمان واقعی آن است، چون قوانین تحلیل به `created` تیکت‌ها و حرکات انبار نگاه می‌کنند.
- **۷ روز اخیر، از API خود اپ و با کاربران آزمایشی هر نقش:**
  - **مصرف انرژی:** با مدیر انرژی.
  - **تیکت‌ها:** با کارمندِ دپارتمان گزارش‌دهنده:

    | دپارتمان گزارش‌دهنده | نقش کاربر |
    |---|---|
    | Housekeeping | `housekeepingStaff` |
    | Front Office | `receptionStaff` |
    | Engineering | `maintenanceStaff` |
    | Security | `operationsManager` |
    | F&B | `restaurantStaff` |
  - **حرکات انبار:** با مسیر `/api/zarin/inventory/{id}/movements` و کاربر انباردار.

  پس هشدارهای `criticalTicket`، `lowStock` و `energySpike` و اعلان مدیران واقعاً از hookها می‌آیند. بعد از ثبت:
  - وضعیت بعدی تیکت (مسئول، SLA، حل‌شدن، هزینه) بی‌صدا اعمال می‌شود؛
  - `created` تیکت، رویداد «created» آن و حرکات انبار به زمان واقعی برگردانده می‌شوند؛
  - هشدار تیکت‌هایی که در داده حل یا بسته شده‌اند، بسته می‌شود.
- **انبار:** اپ موجودی منفی را رد می‌کند (`insufficient_stock`). در دادهٔ ۷ روز اخیر، چند برداشتِ صبح پیش از تحویلِ همان روز ثبت شده‌اند و جمع روزانه هم گردشده است. برای همین:
  - ۶ حرکت تا رسیدن تحویل همان روز صبر می‌کنند؛
  - ۲ حرکت به اندازهٔ موجودی محدود می‌شوند؛
  - ۲ سطر «Import reconciliation» در ساعت 23:59 روز قبل، موجودی پایانی را دقیقاً برابر `inventoryItems.csv` می‌کنند.
- **انرژی:** در ۷ روز اخیر هیچ روزی از آستانهٔ هشدار (+15٪ خط پایه) بالاتر نیست، پس پیش‌فرض هیچ `energySpike` نمی‌سازد. برای آزمودن هشدار انرژی، `--energy-days 30` را اضافه کنید تا مصرف ۳۰ روز اخیر از API برود. با این گزینه، هشدارهای ۳۰ روز اخیر همان عددهای شیت `Test_Scenarios` می‌شوند: ۹ برق، ۱۲ آب و ۰ گاز.
- **کاربران و کارکنان:** ۲۲۱ کاربر با نقش و کد ملی آزمایشی ساخته می‌شوند و به رکورد کارمندشان وصل می‌شوند. نام کارمندی که حساب ندارد به شکل `EMP-… — سمت` است.
- **شیفت‌ها:**

  | شیفت در CSV | نوع در اپ | ساعت |
  |---|---|---|
  | Morning | صبح | 07–15 |
  | Evening | عصر | 15–23 |
  | Night | شب | 23–07 |
  | Office | صبح | 08–16 |
  | Split | عصر | 11–21 |

  وضعیت: Present ← `completed`، Scheduled ← `scheduled`، مرخصی و غیبت ← `absent`.
- **اتاق‌ها:** وضعیت اتاق‌ها در آخر کار از `rooms.csv` گذاشته می‌شود. `updated` اتاق‌های خارج از سرویس برابر `status_since` است.
- **تحلیل:** rollup برای ۳۰ روز (2026-09-07 تا 2026-10-06)، بینش‌ها و بررسی SLA با «now» شیت سناریوها اجرا می‌شوند تا با آن قابل مقایسه باشند.

## نتیجهٔ اجرای آزمایشی

همهٔ مراحل بالا روی یک PocketBase محلی اجرا شدند. hookهای سرور همین مخزن بودند و محدودیت نرخ درخواست مثل سرور واقعی روشن بود. یک هتل `active` هم به‌جای هتل واقعی روی سرور بود. نتیجه:

| بخش | نتیجه |
|---|---|
| بینش‌ها (۱۶ مورد) | ✓ همه. عنوان، اولویت و صرفه‌جویی ماهانه یکسان است: ۱۱ پیش‌بینی اتمام موجودی، ۴ خرابی تکراری، اتاق‌های خارج از سرویس با 4,807,916,164 ریال، و کارایی نظافت 27٪. دو قاعده‌ای که نباید فعال شوند، فعال نشدند |
| rollup روز 2026-10-06 (۱۱ شاخص) | ✓ همه: اشغال 66.1٪، ADR، RevPAR، برق 19,769 kWh (9.8٪ بالای خط پایه)، تیکت‌های باز، دیرکرد و بحرانی (9، 6، 3)، نظافت تخلیه 44.3 دقیقه، کمبود موجودی 5، اتاق خارج از سرویس 3 |
| هشدارها | ✓ تیکت بحرانی 32، SLA همان ۶ تیکت، کمبود موجودی همان ۵ قلم، انرژی ۰ در ۷ روز اخیر |
| تابلوی اتاق‌ها | ✓ occupied 257، vacantClean 195، vacantDirty 14، cleaningInProgress 6، outOfOrder 3 |
| گردش کار نظافت | ✗ سناریو کارهای «pending / inProgress» عصر 2026-10-06 را انتظار دارد، ولی در `tasks.csv` هر ۱۲,۱۱۶ کار `done` هستند. شیت `Housekeeping_Tasks` که سناریو به آن ارجاع می‌دهد در این بسته نیست |
| ۹ سناریوی دیگر | دستی: داشبوردها، گزارش PDF، گردش کار تعمیرات و انبار، شیفت‌ها، دستیار AI، گزارش صبحگاهی n8n، کنتور هوشمند، پیش‌بینی |

بررسی‌های دیگر:

- `created` همهٔ تیکت‌ها، کارها و حرکات انبار برابر زمان واقعی است.
- هیچ هشداری از تاریخچه ساخته نشد.
- `updated` هر سه اتاق خارج از سرویس برابر `status_since` است.
- ورود یک کاربر آزمایشی با کد ملی و رمز موقت کار کرد و `mustChangePassword=true` بود.
- هتل `active` دست‌نخورده ماند.
- حذف با `reset-demo` حدود ۲۵ ثانیه طول کشید و هتل دیگر دست‌نخورده ماند.
- import دوباره بعد از `reset-demo`، با `--energy-days 30`، هشدارهای انرژی ۳۰ روز اخیر را دقیقاً مثل شیت ساخت: برق ۹ (۱ بحرانی)، آب ۱۲ (۱ بحرانی)، گاز ۰.

## بعد از import

- **ورود کاربران آزمایشی:** با کد ملی آزمایشی و رمز موقت وارد اپ می‌شوند و باید رمز را عوض کنند.
- **cronهای سرور:** این cronها (SLA، rollup شبانه، بینش‌ها) برای هتل آزمایشی هم با **زمان واقعی** اجرا می‌شوند. پس عددها کم‌کم از عکس لحظهٔ 2026-10-07 09:30 فاصله می‌گیرند. مثلاً تیکت‌های باز دیرکرد پیدا می‌کنند و روزهای مانده تا اتمام موجودی کم می‌شود.
- **مقایسهٔ دوباره:** مقایسه با وضعیت فعلی سرور، بدون نوشتن چیزی:
  ```zsh
  ZH_PB_URL=https://zarin-hoshmand-nieplltrhr.liara.run npm run import-dataset -- --csv ~/Downloads/app_import_csv_S1_Normal.zip --xlsx ~/Downloads/ParsianAzadi_Zarin_TestDataset_S1_Normal.xlsx --report <شناسهٔ هتل>
  ```

## برگرداندن

- **حذف هتل آزمایشی (پیشنهادی):**
  ```zsh
  HOTEL_ID=<شناسهٔ هتل> ZH_PB_URL=https://zarin-hoshmand-nieplltrhr.liara.run npm run reset-demo
  ```
  اسکریپت فهرست چیزهایی را که پاک می‌شوند نشان می‌دهد و `yes` می‌خواهد. هتل آزمایشی با همهٔ داده‌هایش و ۲۲۱ کاربرش پاک می‌شود. هتل‌های دیگر دست نمی‌خورند. بعد از آن می‌توانید دوباره import کنید.
- **بازگرداندن کل دیتابیس:** در پنل `/_/` ← Settings ← Backups، فایل `zarin-before-import-…zip` را Restore کنید. کل دیتابیس به لحظهٔ قبل از import برمی‌گردد و **هر تغییر بعد از آن، از جمله در هتل واقعی، از بین می‌رود.** فقط وقتی سراغ این راه بروید که `reset-demo` کافی نباشد.

## عیب‌یابی

| پیام | کار لازم |
|---|---|
| `the server's hooks are older than this script` | مرحلهٔ ۲ راهنمای لیارا را اجرا کنید |
| `a hotel named «Parsian Azadi – TEST» already exists` | import قبلی هنوز روی سرور است. دستوری که در همان پیام چاپ می‌شود (`reset-demo`) را اجرا کنید، یا با `--name` نام دیگری بدهید |
| `… test national IDs already belong to users on this server` | کاربران یک import قبلی مانده‌اند. همان هتل را با `reset-demo` حذف کنید |
| `Import stopped: …` | دستور حذف هتل نیمه‌کاره چاپ می‌شود. هتل‌های دیگر دست نخورده‌اند. پس از رفع مشکل، دوباره import کنید |

گزینه‌های دیگر:

| گزینه | کار |
|---|---|
| `--name "…"` | نام دیگری برای هتل آزمایشی |
| `--as-of "2026-10-07 09:30"` | لحظهٔ مبنا به وقت تهران |
| `--recent-days 7` | تعداد روزهایی که از API اپ می‌روند |
| `--energy-days 30` | پنجرهٔ API برای مصرف انرژی |
| `--backup-dir <پوشه>` | محل ذخیرهٔ بکاپ و گزارش |
| `--yes` | بدون پرسیدن `yes` |
